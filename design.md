# Дизайн SvirisTel (svt)

Программный модуль платформонезависимой реализация p2p протокола канального уровня на C.

Изначально SvirisTel ориентирован на работу поверх UART, но не привязан к нему и потенциально может применяться поверх любого протокола физического уровня. Однако SvirisTel не реализует символьную (байтовую) синхронизацию (старт/стоп биты), характерную для канального уровня, и это стоит учитывать, в случае непредусмотренного применения.

## Технологический стек

- Чистый C99, без внешних зависимостей.
- Фрейминг COBS (Consistent Overhead Byte Stuffing).
- Контрольная сумма CRC-16/IBM-SDLC, табличная реализация.

## Глоссарий

- Кадр - последовательность данных закодированная в кадр COBS.
- Чанк - часть данных в кадре COBS не содержащая нулей (между кодами COBS).
- Поток - непрерывный набор принимаемых или передаваемых данных.
- Сегмент - часть данных из потока или любой другой области памяти программы (Кадр, SDU, PDU и т.д.).
- SDU - необрабатываемые пользовательские данные верхнего уровня.
- PDU - незакодированная COBS структура данных включающая служебные поля протокла и SDU.
- Пользователь - разработчик использующий данную реализацию SvirisTel.
- Пользовательский контекст - код написанный разработчиком в котором применяется API SvirisTel.
- Микробатчинг - обработка передаваемых или получаемых данных небольшими порциями.
- Кодирование - формирование передаваемого кадра в соответствии с протоколом COBS.

## Структуры передаваемых данных

### PDU

```
+-----+-----+-----+--------+
| PID | SDL | SDU | CRC-16 |
+-----+-----+-----+--------+
```

| Поле | Размер  | Описание                            |
| ---- | ------- | ----------------------------------- |
| PID  | 1B      | Protocol ID.                        |
| SDL  | 2B      | Длина полезной нагрузки, BigEndian. |
| SDU  | (SDL)B  | Полезная нагрузка (SDU).            |
| CRC  | 2B      | CRC-16/IBM-SDLC, BigEndian.         |

Физический MTU = 65535 B (ограничен полем SDL).
Рекомендуемый MTU = 4092 B (4095-1:PID-2:SDL). Для обеспечения точности работы CRC-16.

CRC-16/IBM-SDLC: полином `0x1021`, init `0xFFFF`, refin=false, refout=true, xorout `0xFFFF`.
Вычисляется над `PID + SDL + SDU` в порядке следования байт на проводе (BigEndian).

### Кадр COBS

```
+-----+---------+-----+---------+-----+     +-----+---------+-----+
| OHB | Chunk 1 | OHB | Chunk 2 | OHB | ... | OHB | Chunk N | FDL |
+-----+---------+-----+---------+-----+     +-----+---------+-----+
```

| Поле                  | Размер  | Описание                                                              |
| --------------------- | ------- | --------------------------------------------------------------------- |
| OHB (Overhead Byte)   | 1B      | Указатель на следующий за чанком непередаваемый 0x00.                 |
| FDL (Frame Delimiter) | 1B      | Разделитель кадров = 0x00.                                            |
| Chunk                 | 0..254B | Последовательность от 0 до 254 произвольных байт не содержащая нулей. |

При кодировании массива данных, каждый байт со значением идентичным FDL, заменяется на OHB.

Начало массива дополняется еще одним OHB.

Каждый OHB имеет значение количества байт относительной позиции следующего OHB.

Если следующий OHB находится дальше 254 байт, то текущий содержит значение 255, а на позицию через 255 байт врезается форсированный OHB.

Форсированный OHB не заменяет байт массива, он вставляется между данными принудительно и также указывает на следующий OHB.

В конец массива добавляется FDL, и последний OHB указывает на него.

## Архитектура

### Объектно ориентированный подход реализации

Реализация SvirisTel определяет структуру контекста которая передается в каждую функцию API для выполнения операции в контексте конкретного экземпляра SvirisTel.

Структура контекста хранит уникальные для экземпляра SvirisTel таблицу колбэков, параметры и состояние, что позволяет обслуживать несколько независимых линков/портов.

### Политика использования памяти

SvirisTel не имеет больших промежуточных буферов внутри, заисключение ограниченного статичного буфера кодирования передаваемых данных. 

### Микробатчинг потоковой обработки данных

Потоковая обработка данных реализована с использованием микробатчинга для сокращения операций обработки и передачи данных. 
Основная идея микробатчинга - работа с сегментами потока данных вместо обработки каждого отдельного байта.

## User story

### Передача данных

Для передачи данных необходимо выполнить действия:

1. Зарегистрировать необходимые колбэки в SvirisTel.
2. Передать указатель на передаваемые данные в SvirisTel.
  SvirisTel вычислит CRC и подготовит служебные поля кадра. С этого момента изменять передаваемые данные нельзя, они используются на протяжении всего процесса передачи. 
3. Периодически опрашивать состояние SvirisTel.
  Во время опроса состояния, SvirisTel производит вызов колбэка для отправки данных в сеть.
  SvirisTel предпринимает единственную попытку передачи данных, поэтому необходимо либо передать их в сеть полностью за единственный вызов колбэка или использовать буфер, если интерфейс не способен обработать полученную в колбэке порцию данных за раз.
4. Когда SvirisTel передал кадр полностью, вызывается колбэк завершения передачи кадра.
  С этого момента разрешено вновь изменять передаваемые данные.

Передачу кадра можно прервать и сбросить состояние передатчика SvirisTel в любой момент. Это может быть полезно для обработки таймаута или иной ошибки на других уровнях используемого сетевого стека. При прерывании передачи кадра, также вызывается колбэк завершения передачи кадра.

Если вызван колбэк отправки данных в сеть, попытаться отправить данные полученные в колбэке в сетевой интерфейс или сложить в буфер для последующей отправки.
Если вызван колбэк завершения отправки данных, разрешить операции записи над памятью хранения передаваемых данных.

### Прием данных

Для извлечения SDU из принимаемого потока сырых байт необходимо:

1. Зарегистрировать необходимые колбэки в SvirisTel.
2. Зарегистрировать SDU. Регистрация определяет метаданные необходимые для приема и передачи SDU.
3. Собрать некоторое количество принятых байт в буфер, таким образом отделив сегмент непрерывного потока принимаемых байт
4. Передать сегмент в SvirisTel на обработку. С этого момента сегмент в буфере становится нелегитимным, так как декодер COBS перезаписывает его. после передачи сегмента в SvirisTel, сегмент обработается синхронно, и будет возвращено количество потребленных байт из сегмента. Во время обработки сегмента могут вызываться колбэки начала приема кадра и приема сегмента или полного SDU. Если кадр принят полностью или выявлена ошибка структуры кадра вызывается колбэк завершения приема кадра с передачей кода легетимности кадра.

SvirisTel может обрабатыввать как кадры целиком, так и их отдельные сегменты, для этого он хранит состояние между вызовами обработки сегментов.
Прием кадра можно прервать между вызовами обработки сегментов и сбросить состояние приемника SvirisTel. При этом также вызывается колбэк завершения приема кадра но с гарантированной передачей кода нелегетимности кадра.

Если вызван колбэк начала приема кадра (колбэк получает ID и длинну принимаемых данных), необходимо подготовиться к буферизации принимаемых данных (инициализировать память, прекратить зависимые процессы).
Если вызван колбэк приема данных, сложить принятый сегмент данных в конец буфера принимаемых данных.
Если вызван колбэк завершения приема с кодом нелегетимности кадра, то необходимо сбросить состояние приема SDU.
Если вызван колбэк завершения приема с кодом легетимности кадра, то можно выполнить пользовательскую обработку принятых данных.

Если в сегменте несколько кадров, то каждый кадр будет обрабатываться в отдельном вызове обработки сегмента.

## API

### Публичные типы данных

```c
// структура контекста
typedef struct {
    struct {
        uint8_t header[4];         // {OHB, PID, SDL_H, SDL_L}
        uint8_t* sdu;              // указатель на передаваемые данные
        uint8_t trailer[2];        // {CRC_H, CRC_L}
       
        // подструктура непрерывного доступа к данным
        struct {
            const uint8_t* ptr[3]; // Указатели на данные
            size_t         len[3]; // Длины каждого сегмента
            size_t         off[4]; // Накопленные смещения: [0, len0, len0+len1, total]
        } pdu_vbuf;

        uint32_t window_start;     // первый ещё не скопированный байт PDU
        uint32_t window_end;       // конец окна (не включая)
        uint32_t ohb_pos;          // позиция в PDU, где должен стоять очередной OHB
        bool insert_mode;          // false: в ohb_pos лежит ноль (placeholder или данные 0x00), OHB его заменяет
                              // true: в ohb_pos данные, OHB нужно вставить перед ними (после кода 0xFF)
    } tx;
    
    struct {
        bool in_frame;      // 1 — идёт приём кадра, 0 — ожидание разделителя (синхронизация)
        bool ohb_forced;    //следующий OHB форсированный (вставлен в разрез PDU, не заменяет 0)
        uint8_t pid;
        uint16_t sdl;
        uint16_t crc;
        uint32_t ohb_pos;   //позиция следующего OHB относительно начала обрабатываемого сегмента
    } rx;
} svt_ctx_t;


// структура указателей на обработчики колбэков
typedef struct {
    // Отправка данных в физический интерфейс
    void (*on_tx_write) (svt_ctx* ctx, uint8_t* data, uint32_t size);
    // Завершение передачи с кодом результата
    void (*on_tx_end) (svt_ctx* ctx, uint8_t result);
    
    // Уведомление о начале приёма кадра
    void (*on_rx_start) (svt_ctx* ctx, uint8_t id, uint16_t length);
    // Осуществлен прием данных
    void (*on_rx_data) (svt_ctx* ctx, uint8_t* data, uint32_t size);
    // Завершен приём кадра
    void (*on_rx_end) (svt_ctx* ctx, uint8_t result);
} svt_cb_t;

 
```

### Публичные функции

``` c
// Инициализировать контекст
void svt_init(svt_ctx* ctx, svt_cb* callbacks);

// Принудительно прекратить процесс передачи данных
void svt_reset_tx(svt_ctx* ctx);

// Передать данные в сеть
void svt_tx(svt_ctx* ctx, uint8_t id, uint8_t* payload, uint16_t size);

// Принудительно прекратить процесс приема кадра
void svt_reset_rx(svt_ctx* ctx);

// Отбработать принятый сегмент потока из сети
void svt_rx(svt_ctx* ctx, uint8_t* segment, uint32_t size);

// Опросить состояние
void svt_poll(svt_ctx* ctx);
```
